# Adjacent methods and the defensible novelty boundary

## 1. Novelty claim that can survive hostile review

ODSA must not be presented as the first sensitivity analysis, the first
multiverse or a general solution to measurement validity. The defensible claim
is narrower:

> Outcome-Definition Sensitivity Analysis is a formal inference-control audit
> for categorical outcome maps. It registers substantively defensible
> state-to-outcome definitions, separates their level, composition,
> association and subgroup-order consequences and checks whether the claims
> attached to each definition remain compatible with every state counted as
> positive.

The distinctive feature is not merely running several recodings. It is the
explicit linkage among the observed state register, definition relations,
positive-class composition and claim admissibility when alternative
definitions may answer different questions.

## 2. Comparison with adjacent approaches

| Approach | Primary object | Shared ground | Boundary ODSA must preserve |
|---|---|---|---|
| Multiverse analysis | Results across reasonable data-processing choices | Both expose sensitivity to defensible construction choices | A multiverse commonly evaluates a focal finding across alternative processed datasets. ODSA first asks whether the alternative outcomes still represent the same question. It does not treat semantically different definitions as interchangeable branches. |
| Specification curve analysis | Results across theoretically justified, statistically valid and non-redundant model specifications | Both require an explicit specification set and complete reporting | Specification curves include graphical display and joint inference. ODSA does not pool definitions that represent different constructs or managerial questions. |
| Many-analyst analysis | Variation produced by independent analytical teams | Both reveal that defensible choices can alter conclusions | ODSA is a prespecified audit of outcome construction, not a crowdsourced estimate of analyst heterogeneity. |
| Questionable measurement practices framework | Transparency about construct definition, operationalisation and scoring | Both treat measurement choices as consequential for inference | ODSA cannot establish construct validity. It operates after an observed state register exists and audits what registered definitions preserve or erase. |
| System-use conceptualisation | Context-specific conceptualisation and operationalisation of system use | Both require alignment between measure and theoretical question | ODSA audits several categorical maps but does not replace substantive conceptualisation of users, systems, tasks or organisational context. |
| Item response theory and scale validation | Latent measurement, item properties and scale construction | Both challenge unexamined measurement conventions | ODSA is not a latent-variable model, scale-development method, reliability analysis or test of measurement invariance. |
| Misclassification sensitivity analysis | Bias from erroneous classification against an assumed underlying truth | Both examine category mappings | ODSA's core problem can exist even when each observed state is recorded without error: the definitions may still answer different questions. |

## 3. Why ODSA is not merely a small multiverse

A multiverse or specification curve usually starts from a research question
whose estimand is intended to remain stable while reasonable analytical
choices vary. ODSA permits a more difficult diagnosis: two defensible outcome
definitions may not preserve the same estimand. Active use and
active-or-project engagement are not alternative implementations of one
unchanged concept unless the theory explicitly defines a common broad
construct.

ODSA therefore asks:

1. which states are positive under each definition;
2. which states enter or leave when definitions change;
3. how each positive class is composed;
4. whether association and subgroup order change;
5. whether the same claim remains admissible;
6. whether cross-definition comparison is scientifically meaningful.

When item 6 fails, joint inference across definitions may conceal rather than
resolve the conceptual difference.

## 4. Information Systems positioning

Information Systems research already demonstrates that conceptualising and
operationalising system use differently can change empirical conclusions.
ODSA should be positioned as a specialised extension for categorical outcome
maps, not as a replacement for that literature.

The journal-facing contribution is:

- outcome definition is part of IS construct operationalisation, not a neutral
  coding step;
- categorical broadening can change the organisational object represented by
  a KPI;
- permitted inference must remain compatible with every positive state.

The Romanian AI application is a worked example under severe design
constraints. It cannot validate a universal method by itself.

## 5. Defensible and indefensible wording

### Defensible

- “a formal audit framework for categorical outcome definitions”
- “an inference-control layer”
- “definition-sensitive level, composition, association and subgroup order”
- “claim admissibility under an explicit state register”
- “a worked application and controlled simulation programme”
- “complementary to multiverse and specification-curve approaches”

### Indefensible

- “the first sensitivity analysis of measurement”
- “a new estimator”
- “a universal robustness test”
- “a validated scale”
- “a method that identifies the correct adoption rate”
- “proof that broad measures are invalid”
- “joint evidence across all definitions” when definitions answer different
  questions
